## Technical Implementation

### Semantic Release Pipeline
```
Push to main → Commit Analysis → Version Bump → CHANGELOG Update → 
Git Tag → GitHub Release → Build Artifacts
```

**Key features:**
- Uses Node.js `semantic-release` (not python-semantic-release)
- Poetry integration via `@semantic-release/exec` plugin
- Conventional commits analyzed by `@semantic-release/commit-analyzer`
- CHANGELOG generated by `@semantic-release/release-notes-generator`
- Version updated in pyproject.toml via `poetry version`
- Changes committed via `@semantic-release/git`
- GitHub Release created via `@semantic-release/github`

### PyPI Publishing Pipeline
```
Release Created → Tests Run → Poetry Build → Twine Validation → 
Trusted Publishing (OIDC) → PyPI Upload
```

**Key features:**
- Uses `pypa/gh-action-pypi-publish@release/v1`
- Trusted Publishing (OIDC) for secure, token-less authentication
- Supports both PyPI and TestPyPI environments
- Manual trigger option for testing
- Build artifacts validation with `twine check`

### Poetry Integration

All workflows use Poetry commands:
- `poetry install` - Install dependencies
- `poetry build` - Build wheel and source distribution
- `poetry publish` - Publish to PyPI (manual emergency only)
- `poetry version` - Update version (automated via semantic-release)
